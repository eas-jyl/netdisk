# 第一步实现文档：后端启动、数据库连接、用户注册登录

## 1. 目标

第一步不要急着做文件上传，也不要先做前端页面。

我们先只完成这个最小闭环：

1. Go 服务可以启动
2. 程序可以读取配置
3. 程序可以连接 MySQL
4. 程序可以自动创建 `users` 表
5. 程序提供注册接口
6. 程序提供登录接口
7. 登录成功后返回 JWT Token

只要这一步完成，后面文件上传、权限管理、用户信息等功能就都有了基础。

## 2. 这一步为什么最重要

原项目 `example/` 的核心依赖顺序其实很清楚：

- `main.go` 负责启动应用
- `settings` 负责配置加载
- `db` 负责数据库连接
- `models/user` 负责用户数据
- `services/login` 负责注册和登录
- `middlewares/jwt` 负责后续鉴权

所以第一步的本质，是把“应用底座”和“身份入口”先搭起来。

## 3. 这一步最终要做出的效果

你做完后，应该能完成下面这些操作：

1. 启动服务
2. 访问健康检查接口，返回 `ok`
3. 调用注册接口，创建一个新用户
4. 调用登录接口，拿到一个 JWT Token
5. 数据库里能看到这个用户记录

## 7. User 模型第一版怎么设计

先不要完全复刻原项目的 `accounts_user` 所有字段。

第一版只保留最必要字段：

```go
type User struct {
    ID         uint      `gorm:"primaryKey" json:"id"`
    UUID       string    `gorm:"type:varchar(36);uniqueIndex;not null" json:"uuid"`
    Username   string    `gorm:"type:varchar(64);uniqueIndex;not null" json:"username"`
    Password   string    `gorm:"type:varchar(255);not null" json:"-"`
    CreatedAt  time.Time `json:"createdAt"`
    UpdatedAt  time.Time `json:"updatedAt"`
}
```

先做简化是为了降低第一步难度。后面再扩展：

- `role`
- `status`
- `size_limit`
- `total_size`
- `last_ip`
- `last_time`

## 8. 注册接口应该怎么设计

接口：

```text
POST /api/account/register
```

请求体：

```json
{
  "username": "admin",
  "password": "123456"
}
```

处理逻辑：

1. 校验参数不能为空
2. 检查用户名是否已存在
3. 对密码做哈希
4. 生成用户 UUID
5. 写入数据库
6. 返回用户基本信息

返回示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1,
    "uuid": "xxx",
    "username": "admin"
  }
}
```

## 9. 登录接口应该怎么设计

接口：

```text
POST /api/account/login
```

请求体：

```json
{
  "username": "admin",
  "password": "123456"
}
```

处理逻辑：

1. 根据用户名查用户
2. 校验密码是否正确
3. 生成 JWT Token
4. 返回用户信息和 Token

返回示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "xxxxx",
    "user": {
      "id": 1,
      "uuid": "xxx",
      "username": "admin"
    }
  }
}
```

## 10. 密码为什么不能明文存储

这一步一定要从第一天就养成习惯：密码绝对不要明文入库。

建议使用：

- `bcrypt`

实现原则：

1. 注册时把密码哈希后保存
2. 登录时用哈希比较函数校验

不要这样做：

- 把前端传来的密码直接存进数据库
- 自己手写简单 MD5 方案

## 11. JWT 第一版应该做到什么程度

第一版 JWT 不用设计得太复杂，只要能支撑“登录成功后标识用户身份”即可。

建议在 Token 里放：

- `user_id`
- `username`
- `exp`

你现在只需要实现：

1. 生成 Token
2. 返回给客户端

这一步可以先不做：

- JWT 中间件拦截受保护接口
- 刷新 Token
- 黑名单 Token

不过如果你状态不错，也可以顺手把 `JWT middleware` 预留出来。

## 12. 路由第一版建议

第一步只需要下面 3 个接口：

```text
GET  /ping
POST /api/account/register
POST /api/account/login
```

路由职责：

- `/ping` 用来判断服务是否正常启动
- `/api/account/register` 用来创建用户
- `/api/account/login` 用来登录并拿 Token

## 13. 推荐的分层职责

为了后面复刻完整项目时不乱，第一步就尽量保持分层。

### main

负责：

- 读取配置
- 初始化数据库
- 初始化路由
- 启动 HTTP 服务

### handler

负责：

- 接收请求
- 绑定参数
- 返回 JSON

不要在这里写太多数据库逻辑。

### service

负责：

- 注册业务
- 登录业务
- 密码校验
- Token 生成

### model

负责：

- 表结构定义

### db

负责：

- 连接 MySQL
- 自动迁移

## 19. 最终建议

第一步的关键不是写很多代码，而是把下面这条链打穿：

`启动服务 -> 读取配置 -> 连接数据库 -> 创建用户 -> 登录成功 -> 返回 Token`

只要这条链通了，你后面复刻整个项目会顺很多。

如果你准备开始写代码，最推荐的顺序是：

1. 先写 `config`
2. 再写 `db`
3. 再写 `User model`
4. 再写 `register`
5. 最后写 `login`

不要反过来。

这样你每一步都能看到明确结果，也最容易排错。
